# Заявки общежития

Студенты создают заявки на ремонт, специалисты берут их из очереди и отмечают выполненными, администратор просматривает заявки и управляет специалистами и пресетами.

## Запуск через Docker Compose

Понадобятся Docker и Docker Compose. Скопируйте конфигурацию при первом запуске.

```bash
test -f .env || cp .env.example .env
```

Заполните `SECRET_KEY` и `POSTGRES_PASSWORD` в `.env`. Для каждого значения можно сгенерировать отдельный ключ командой `openssl rand -hex 32`. Чтобы загрузить демо-данные, укажите `SEED_DEMO=true`.

```bash
docker compose up --build -d --wait
```

Откройте [сервис](http://127.0.0.1:8000). Приложение само дождётся PostgreSQL, применит миграции и при `SEED_DEMO=true` загрузит [демонстрационные аккаунты](#демонстрационные-аккаунты). База и фотографии хранятся в томе `postgres_data`.

```bash
docker compose logs -f app  # Журнал приложения
docker compose down         # Остановить контейнеры с сохранением данных
```

## Локальный запуск без Docker

Понадобятся Python 3.11+ и PostgreSQL. В корне проекта установите зависимости и создайте конфигурацию.

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
cp .env.example .env
python - <<'PY'
from pathlib import Path
from secrets import token_urlsafe

path = Path(".env")
path.write_text(path.read_text().replace("SECRET_KEY=\n", f"SECRET_KEY={token_urlsafe(48)}\n"))
PY
```

Подключитесь к PostgreSQL от имени пользователя с правом создания ролей и баз. В примере используется администратор `postgres`.

```bash
psql -U postgres -d postgres
```

```sql
CREATE ROLE dorm LOGIN PASSWORD 'local_dorm_password';
CREATE DATABASE dorm_maintenance OWNER dorm;
\q
```

Когда база доступна, выполните миграции, загрузите демонстрационные данные и запустите сервер.

```bash
alembic upgrade head
python -m app.seed
uvicorn app.main:app --host 127.0.0.1 --port 8000
```

Откройте [сервис](http://127.0.0.1:8000).

## Демонстрационные аккаунты

Для всех логинов пароль `DemoDorm2026!`.

| Логин | Роль | Адрес или специальность |
| --- | --- | --- |
| `student1` | Студент | Общежитие № 1, комната 302, блок А |
| `student2` | Студент | Общежитие № 2, комната 407 |
| `carpenter` | Специалист | Плотник |
| `electrician` | Специалист | Электрик |
| `plumber` | Специалист | Сантехник |
| `admin` | Администратор | — |

Сидер добавляет отсутствующие аккаунты по логину и пресеты по паре «специальность и название». Используйте демонстрационные аккаунты в локальной среде.

## Конфигурация

| Переменная | Назначение |
| --- | --- |
| `DATABASE_URL` | Строка подключения с префиксом `postgresql+psycopg://` для локального запуска без Docker. Compose задаёт параметры подключения через `POSTGRES_*`. |
| `SECRET_KEY` | Случайный ключ подписи сессий длиной от 32 символов. |
| `SESSION_HTTPS_ONLY` | Установите `true` при развёртывании за HTTPS-прокси. Для локального HTTP используйте `false`. |
| `APP_TIMEZONE` | Часовой пояс дат в интерфейсе и границ фильтра по дате. По умолчанию `Asia/Yekaterinburg`. |
| `DEVELOPER_CONTACT` | Контакт разработчика, который отображается в разделе «Контакты». Замените демонстрационное значение на своё. |
| `POSTGRES_PASSWORD` | Пароль PostgreSQL для Docker Compose. Задайте перед созданием тома. |
| `APP_PORT` | Порт приложения на компьютере при запуске через Compose. По умолчанию `8000`. |
| `SEED_DEMO` | `true` включает загрузку демо-данных при запуске контейнера приложения. Для базы с реальными данными используйте `false`. |

## Ручная проверка

1. Войдите как `student1`. Создайте заявку электрику с пресетом, комнатой `502` и фото. Убедитесь, что профиль по-прежнему показывает `302`.
2. Проверьте, что прямые ссылки на карточку и фото недоступны `student2` и специалисту другой специальности.
3. Откройте карточку как `electrician` в двух вкладках. Возьмите заявку в первой. Повторное действие во второй вкладке и отправка ранее открытой формы редактирования от студента должны показать сообщение об изменении заявки.
4. Отметьте заявку выполненной из раздела «Мои заявки» специалиста. Найдите её как администратор, совместив фильтры по исполнителю, специальности, статусу, общежитию и дате.
5. Добавьте и затем отключите пресет. Проверьте оба состояния в форме студента. Измените и отмените другую новую заявку. Она должна остаться в истории.
